## Android Instance-Creation API — Implementation Plan

### Goal
Add standalone API endpoints (separate from `/api/quick`) that the Android app calls to:
1. Create a **temporary** (10-min) instance on every connection — even when unauthenticated.
2. Authenticate the user via **Telegram** (existing flow).
3. **Claim** the temp instance after auth (or immediately if already authenticated): transfer ownership to the user, keep the running process, and **reset its timeout to the full 1h lifetime**. No restart — the session the user just authorized inside the spawned service is preserved.
4. **Explicitly stop** the instance when the user disconnects (clean-shutdown path; the full-lifetime `timeout_at` is the safety net if the app dies).

### Design decisions (confirmed)
- **Gating:** static app token via `WB_APP_TOKEN` config + `X-App-Token` header dependency (mirrors the existing `WB_QUICK_TOKEN` pattern). Disabled → 404 when unset.
- **Temp lifecycle:** token-based handoff. Temp instances run as `user_id=1` (admin) under a 600s timeout, flagged `is_quick=1` so the existing `quick_max_concurrent` cap and reaper/restart-reconciliation logic apply unchanged. No schema migration needed.
- **Claim = ownership transfer + timeout reset:** `UPDATE instances SET user_id=?, is_quick=0, timeout_at=<now+1h>`; cancel the 600s temp `kill_task` in `process_manager`; re-schedule a full-lifetime timeout via existing `schedule_timeout()`.
- **Disconnect = explicit stop:** Android calls `DELETE /api/app/instances/{id}`; server runs existing `process_manager.stop()`.
- **Docs:** OpenAPI/Swagger YAML snippet (`docs/android_api.yaml`) + a short `docs/ANDROID_INTEGRATION.md` README pointing at it and listing flows.

### File changes

#### 1. `config.py` — add two settings
- `APP_TOKEN = os.getenv("WB_APP_TOKEN", "")` — static token gating the Android endpoints (empty = disabled).
- `APP_TEMP_TIMEOUT = int(os.getenv("WB_APP_TEMP_TIMEOUT", "600"))` — temp-instance lifetime (10 min), overridable.
(Reuse existing `DEFAULT_TIMEOUT_SECONDS` for the post-claim full lifetime.)

#### 2. `security.py` — add a FastAPI dependency
- `verify_app_token(request: Request)` → reads `X-App-Token` header, constant-time-compares to `APP_TOKEN`. Empty config → `404 "Android app API disabled"`. Wrong/missing token → `401`. Used as a router-wide dependency.

#### 3. `routers/app.py` — **new** router (prefix `/api/app`, tags `["android"]"]`)
Endpoints (all gated by `verify_app_token`):

- **`POST /api/app/instances`** — create temporary instance (unauthenticated flow).
  - Request: `{"service_id": int?}` (optional; falls back to configured quick service, same as `/quick`).
  - Enforces `quick_max_concurrent` cap (counts active `is_quick=1` rows — same query as `/quick`).
  - Calls `instance_service.start(user_id=1, service_id, timeout_seconds=APP_TEMP_TIMEOUT, is_quick=True)`.
  - Generates a **claim token** (32-byte URL-safe string), stores mapping `claim_token -> instance_id` in memory (a module-level `dict` with a TTL of `APP_TEMP_TIMEOUT`).
  - Response `201`: `{instance_id, claim_token, status, output_link, temp_expires_at, service_name}`.

- **`POST /api/app/instances/{instance_id}/claim`** — transfer a temp instance to the authenticated user.
  - Request: `{"telegram_init_data": str, "claim_token": str}`.
  - Validates initData via existing `validate_telegram_init_data()` (gated by `TELEGRAM_BOT_TOKEN`), resolves/creates the user via `user_service.get_or_create_for_telegram()`.
  - Verifies `claim_token` maps to `instance_id` and the instance is still live; rejects otherwise (`404/410`).
  - `UPDATE instances SET user_id=?, is_quick=0, timeout_at=<now+DEFAULT_TIMEOUT_SECONDS>`.
  - Cancels the temp 600s `kill_task` and reschedules full-lifetime timeout (new helper on `process_manager`).
  - Issues a session token via `create_session(user["id"])` so the app owns the instance under the client flow going forward.
  - Response `200`: `{instance_id, user_id, token, role, username, status, output_link, expires_at}`.

- **`GET /api/app/instances/{instance_id}`** — poll status/output_link (uses claim_token OR bearer). Lightweight check for Android to know if still running / link appeared.

- **`DELETE /api/app/instances/{instance_id}`** — explicit disconnect stop.
  - Request: `{"claim_token": str?}` (for pre-auth) **or** bearer token (post-auth).
  - Calls `process_manager.stop(instance_id)`. Idempotent (already-terminal returns the row).

- **`GET /api/app/health`** — readiness check for the app (returns service availability + whether Telegram auth is enabled). Returns 404 for the whole router if `APP_TOKEN` unset.

#### 4. `process_manager.py` — add `reschedule_timeout(instance_id, delay)`
- Look up `tracked = self._tracked.get(instance_id)`; if it has a `kill_task`, cancel it.
- Recompute/store new `timeout_at` happens in the router (DB update); this method just cancels the old timer task and calls `schedule_timeout(instance_id, delay)` to arm the new full-lifetime timer. Keeps the cancel+reschedule atomic under `self._lock`.

#### 5. `main.py` — register the router
- `from routers import app as app_router` → `app.include_router(app_router.router)` alongside the others.

#### 6. `.env.example` / `env.example` — document new vars
Add `WB_APP_TOKEN` and `WB_APP_TEMP_TIMEOUT` with comments.

#### 7. `docs/android_api.yaml` — **new** OpenAPI 3.0 snippet
A standalone OpenAPI document fragment describing the `/api/app/*` and `/api/auth/telegram` endpoints (paths, schemas, securityScheme `AppToken` + bearer, examples, error codes). Importable by Android HTTP clients / code generators.

#### 8. `docs/ANDROID_INTEGRATION.md` — **new** README
Concise guide: env setup, the full connect→temp-instance→auth→claim→disconnect sequence (ASCII), Telegram initData note (Android must obtain it via the Telegram Bot WebApp SDK), error-code table, and a pointer to the OpenAPI yaml.

### Reuse (no duplication)
- Temp instances piggyback on the **existing** `is_quick` machinery: cap check, reaper, restart reconciliation, `output_link` tailer all work unchanged.
- Auth reuses `validate_telegram_init_data`, `get_or_create_for_telegram`, `create_session` — no new crypto or user-creation logic.
- Service resolution reuses the quick flow's configured-service lookup.
- Stop reuses `process_manager.stop()`.

### Behavior summary for the Android team
1. App start → `POST /api/app/instances` → get `{instance_id, claim_token, output_link}` (instance is temp, 10-min TTL).
2. User authorizes *inside* the spawned service during those 10 minutes.
3. App calls `POST /api/app/instances/{id}/claim` with Telegram initData + claim_token → ownership transferred, TTL reset to 1h, session token returned.
4. If the user was **already authenticated** (app has a valid bearer from a previous session), `claim` is called immediately — same path.
5. On app close/disconnect → `DELETE /api/app/instances/{id}`. If the app crashes, the 1h `timeout_at` kills it.

### Out of scope (deliberately)
- No new DB table / no schema migration.
- No WebSocket/SSE/heartbeat — explicit stop only (confirmed).
- No restart-on-claim (preserves the user's in-instance authorization).

### Verification
- Restart server, hit `POST /api/app/instances` with `X-App-Token` → expect temp instance + claim_token.
- `DELETE` → instance stops. Claim flow with valid/invalid initData. Cap enforcement returns 429. Unset `WB_APP_TOKEN` → whole router 404.
- Run `python -c "import main"` to confirm imports; optionally start uvicorn and curl the endpoints.
