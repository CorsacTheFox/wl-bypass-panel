# Новый флоу авторизации приложения: ссылка подписки Remnawave → bearer-сессия

Telegram-бот остаётся только для ПК (mini app → клиентская страница, без изменений). Приложение переходит на self-service вход по ссылке подписки. Старые APK продолжают работать (initData-пути сохранены). Структура БД не меняется.

## Бэкенд (Whitelist_test)

### 1. `remnawave.py` — разрешение подписки
- `fetch_users()`: добавить в entry аддитивные поля `subscription_id` = `u["subscriptionId"]`, `subscription_user_name` = `u["subscriptionUserName"]` (существующие вызовы не меняются).
- Новый метод `RemnawaveMigrationService.find_user_by_subscription(token)`:
  - сквады берёт из `get_sync_options()["squads"]` (если пусто — RemnawaveError «no squads configured»);
  - итерирует `client.iter_users()` (raw-словари), матчит `subscriptionId == token` (точно), затем `subscriptionUserName == token` (без учёта регистра);
  - in-memory кэш token→user с TTL 300с, чтобы не дёргать панель на каждый вход.

### 2. `services.py` (маленькое)
- `UserService.find_by_external_ref(external_ref)` — один SELECT (аналог find_by_telegram).

### 3. `routers/app.py` — три правки
- **Новый `POST /api/app/auth/link`** (гейт X-App-Token как у всего роутера), body `{"subscription": "<url|token>"}`:
  1. извлечь токен из URL (последний сегмент после `/sub/` или `/c/`) или взять как есть;
  2. разрешить через `find_user_by_subscription` → 401 «not found» если нет;
  3. статус != ACTIVE → 403 «subscription expired»;
  4. локальный юзер по `external_ref`; если нет — создать на лету как синк (`create_client(username=…, external_ref=uuid, telegram_id=…, can_create_instances=<опция синка>, must_change_password=False)`; при конфликте username — фолбэк `user_<tg_id>` / `remna_<uuid8>`);
  5. вернуть `{"token","role","username","must_change_password":false}` (форма LoginOut).
- **`POST /api/app/instances`**: опциональная bearer-идентификация (новый `optional_user`-dependency: без заголовка → None, битый → 401). Если нет `telegram_init_data`, но есть bearer — существующие ветки reuse/create+claim работают от этого юзера. initData-путь остаётся для старых APK.
- **`POST /api/app/instances/{id}/claim`**: принимать bearer вместо `telegram_init_data` (claim_token обязателен по-прежнему; при обоих — initData выигрывает).
- **`GET /api/app/health`**: добавить `"link_auth": remnawave.is_configured()` (аддитивно).

### 4. Не трогаем
`/api/auth/telegram`, `/tg-auth`, `/tginit`, `/quick`, SPA, манифест бота — всё остаётся для ПК/легаси.

## Приложение (android-app)

### 5. `CorsClient` + `Models`
- `authLink(subscription): LoginOut` → POST /api/app/auth/link; `claim(...)` — опциональный bearer вместо initData; `createInstance(... bearer)`; `Health` + поле `link_auth`.

### 6. Новый `CorsSignInSheet` (по образцу AddXraySubscriptionSheet)
Одно поле «ссылка подписки», paste-chip, inline-ошибка, loading. Точка входа — существующие CTA `corsSignInButton` и строка Account в Settings.

### 7. `MainActivity`
- Кнопка «Sign in» открывает `CorsSignInSheet` (Telegram-инициация `signInWithTelegram()` удаляется; intent-фильтры и парсинг колбэков остаются — старые ссылки не ломаются).
- `refreshCorsAuthPrompt` ориентируется на `!Prefs.corsSignedIn`.
- Успех входа: `Prefs.corsSessionToken`, `corsUsername` + **`corsSubscriptionLink` (новый ключ — для тихого пере-логина)**, затем `resumeClaim()` при активном флоу.
- Строки en+ru («Sign in with subscription», ошибки).

### 8. `CorsInstanceController`
- `start()`: гейт здоровья — вместо `telegram_enabled` → `telegram_enabled || link_auth`.
- `createInstanceResilient()`: приоритет bearer (`corsSessionToken`) → легаси initData → анонимно. При 401: если сохранён `corsSubscriptionLink` — тихий `authLink()` и повтор; иначе очистка токена + показать кнопку входа.
- `tryClaim()`: bearer, когда initData нет.

### 9. QR-сканер (маленькое)
MainFragment: отсканированная http(s)-ссылка с `/sub/` открывает `CorsSignInSheet` с prefill (сейчас гейтится только xray-ссылками).

## Порядок и проверки
1. Бэк: юнит-тесты `auth/link` (мок Remnawave-клиента: happy/401/403/авто-создание), смоук `instances` с bearer, `py_compile`.
2. Деплой бэка (аддитивно, ничего не ломает).
3. Пересборка APK (`./gradlew assembleDebug`, подпись та же) и установка на Android 12 + 16.
4. Смоук приложения: вход по ссылке → connect → heartbeat; ПК-флоу через бота — регресс.

Риски/заметки: ссылка подписки хранится в Prefs рядом с bearer (тот же класс секрета, что уже хранит XraySubscriptionManager); сессия 12ч — тихий пере-логин закрывает вопрос; если панель недоступна — 502 с понятным detail.
