# Remnawave → Panel user migration (backend + admin UI)

## Goal
Import users from selected squads of a Remnawave panel (`/api` spec v3.2.3) into this Whitelist-Bypass Instance Manager: read-only from Remnawave, manual "Preview/Migrate" from the admin UI, plus an optional recurring auto-sync. Local accounts are created through the existing `user_service.create_client(...)` seam (`external_ref` = Remnawave UUID ⇒ idempotent re-runs).

## Remnawave API facts (verified against official backend/SDK sources)
- Auth: `Authorization: Bearer <API_KEY>`; base `<panel-url>/api`
- `GET /api/system/metadata` → panel version (connection test)
- `GET /api/internal-squads` → `{response:{total, squads:[{uuid,name,…}]}}`
- `GET /api/users?start=0&size=100&filters=[{"id":"activeInternalSquads","value":"<squad-uuid>"}]` (`filters` is a JSON-encoded string) → `{response:{users:[…], total}}`; user fields used: `uuid, username, status, expireAt, telegramId`

## Files

### 1. New `remnawave.py` (core integration)
- `RemnawaveClient` — thin `httpx.AsyncClient` wrapper: normalizes base URL (strip trailing `/` and `/api`), Bearer auth, timeout (env `WB_REMNAWAVE_TIMEOUT`, default 15s), maps HTTP/network errors to `RemnawaveError` (401/403 → "invalid API key", JSON `message/detail` surfaced).
  - `get_metadata()`, `get_internal_squads()`, `iter_users(squad_uuid)` (paginates `size=100` until `total` reached; hard cap 10 000 users/run).
- Config store (reuses existing `settings` table, no schema change): keys `remnawave_panel_url`, `remnawave_api_key` (env fallback `WB_REMNAWAVE_PANEL_URL` / `WB_REMNAWAVE_API_KEY`), `remnawave_auto_sync_enabled`, `remnawave_auto_sync_interval_min` (default 30), `remnawave_auto_sync_squads` (JSON uuid list), `remnawave_sync_only_active` (default 1), `remnawave_sync_grant_create` (default 0), `remnawave_sync_max_concurrent`, `remnawave_last_sync` (JSON run summary). API key never returned raw — masked preview only.
- `RemnawaveMigrationService`:
  - `list_squads()`; `fetch_users(squad_uuids, only_active)` — dedupes users across squads by uuid.
  - Classify vs local DB: **new** / **already migrated** (same `external_ref`) / **username conflict** (same username, `COLLATE NOCASE`).
  - `preview(...)` → counts + first 200 users (`username, status, expire_at, telegram_id, category, squad`).
  - `migrate(...)` → per user: `user_service.create_client(username, password=None, external_ref=uuid, telegram_id=rw.telegramId, max_concurrent=opt, can_create_instances=opt)`; per-user errors captured; returns report `{total, created, skipped_existing, skipped_conflict, filtered_inactive, errors[]}`. Never writes to Remnawave.
- `RemnawaveSyncService` — background asyncio loop (mirrors `process_manager` pattern): `start()/stop()`; re-reads settings each cycle; first run ~15s after boot, then every N minutes; writes `remnawave_last_sync`; disabled/no-credentials ⇒ idle.

### 2. New `routers/remnawave.py` (admin-only, `require_admin`)
- `GET  /api/admin/remnawave/config` — url, masked key, auto-sync settings, `last_sync`
- `PUT  /api/admin/remnawave/config` — partial update; empty `api_key` = keep current
- `POST /api/admin/remnawave/test` — calls `/system/metadata`, returns version
- `GET  /api/admin/remnawave/squads`
- `POST /api/admin/remnawave/preview` `{squads[], only_active}`
- `POST /api/admin/remnawave/migrate` `{squads[], only_active, grant_create_instances, max_concurrent}`
Registered in `main.py` alongside other routers.

### 3. `main.py` — lifespan: start/stop `remnawave_sync` (after `process_manager.start()`).

### 4. `static/index.html` — new admin tab **"Remnawave"** (`buildNav`, `sec-remnawave`, `switchTab`, `refreshRemnawave`), same dark style:
- **Connection card**: panel URL + API key (password field, blank = keep), Save + Test, version status line.
- **Squads card**: Load squads → checkbox chips (uuid shown), migration options (skip non-ACTIVE, grant instance creation, max slots), **Preview** → summary counts + result table, **Migrate** → report toast + detailed result.
- **Auto-sync card**: enable toggle, interval (minutes), last-sync summary; saves selected squads+options via `PUT /config`.
- Clients table: violet `rw` badge for users created from Remnawave (`external_ref` already returned by API).

### 5. Housekeeping
- `requirements.txt`: add `httpx>=0.27`; install into `.venv`.
- `config.py`: env fallbacks (`WB_REMNAWAVE_*`), `TIMEOUT_SECONDS`.
- `.env.example` + README (endpoints, env vars, behavior).

## Defaults
Migrated users: no password (must set on first login — existing pattern), `can_create_instances=off` (existing policy), slots = global default, `telegram_id` linked when free. Read-only against Remnawave; idempotent re-runs.
