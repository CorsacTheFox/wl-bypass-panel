Refactor the Whitelist-Bypass Instance Manager into a Telegram Mini App while preserving the existing username/password web auth and all current UI capabilities.

## Key decisions (confirmed)
- **Existing clients keep access**: one-time migration backfill sets `can_create_instances=1` for already-existing users; the column DEFAULT is 0 so all NEW users start disabled.
- **Telegram login**: match an existing local user by `telegram_id` → else by username (NOCASE) → else auto-create a passwordless client.

## Changes by file

**config.py** — add `TELEGRAM_BOT_TOKEN` (empty = TMA auth disabled, mirroring `QUICK_TOKEN`) and `TELEGRAM_INIT_DATA_MAX_AGE` (replay window).

**db.py** — add to `users`: `telegram_id INTEGER` (nullable, partial unique index) and `can_create_instances INTEGER NOT NULL DEFAULT 0`. Idempotent `ALTER TABLE` migrations in `connect()`; the backfill `UPDATE users SET can_create_instances=1` lives inside the "column missing" guard so it runs once on upgrade.

**security.py** — add `validate_telegram_init_data(init_data, bot_token, max_age)` (stdlib HMAC-SHA256 with key=b"WebAppData"/msg=bot_token, then HMAC over data-check-string, constant-time compare, auth_date replay check) and `TelegramAuthError`. Extend `get_user_by_token` to select/return `can_create_instances`.

**services.py** —
- `UserService`: include new columns in `get`/`list_clients`/`authenticate`; add `find_by_telegram`, `find_by_username`, `link_telegram`, `get_or_create_for_telegram`, `set_can_create_bulk`; extend `create_client`/`create_admin` with `telegram_id`/`can_create_instances`/`must_change_password` kwargs (admins always True; admin-router-created clients stay default-off); extend `update()` with `can_create_instances`.
- `InstanceService.start`: enforce `if role != "admin" and not can_create_instances: raise ForbiddenError` right after the concurrency check. Add `class ForbiddenError`.

**routers/telegram.py** (new) — `POST /api/auth/telegram {initData}` → validate, get_or_create user, `create_session`, return same shape as `/api/auth/login`.

**routers/auth.py** — `/api/auth/me` returns `can_create_instances`.

**routers/client.py** — `start_call` maps `ForbiddenError → 403`.

**routers/admin.py** — add `can_create_instances` to `ClientUpdate`; new `POST /api/admin/clients/can-create {usernames, value}` for bulk grant/revoke.

**main.py** — include the telegram router.

**static/index.html** (additive) — load `telegram-web-app.js`; in the init IIFE, if `Telegram.WebApp.initData` is present, call `ready()/expand()`, POST `/api/auth/telegram`, then reuse the existing `bootstrap()`. Disable the dashboard Start button + show a notice when `role !== 'admin' && !can_create_instances`. Admin UI: add a "Create?" badge column to the Clients table, a "Can create instances" checkbox in the Edit Client modal, and a "Grant Access" button+modal that POSTs to the new bulk endpoint.

**README.md** — document TMA setup (BotFather, `WB_TELEGRAM_BOT_TOKEN`, Mini App URL) and the privilege model.

## Backward compatibility
All additive: no endpoint/query/column removed; username/password login untouched; existing clients retain access via backfill; new users + TG users default OFF; admins always allowed; no new pip dependencies.
