## Goal
A `systemctl restart wb-manager` must NOT mark running instances as `crashed`. The spawned binaries (in their own session via `start_new_session=True`, and `KillMode=mixed` in the systemd unit) survive the restart as orphan OS processes. On startup, the manager should **re-adopt** them — reattach supervision (waiter + tailer + timeout reschedule) to the still-living PID, and only mark `crashed` the ones whose PID is genuinely gone.

## Root cause
`main.py:_reconcile_stale_instances()` unconditionally marks every live DB row as `crashed` with error `"process orphaned by server restart"`, without checking whether the PID is actually still running.

## Changes

### 1. `process_manager.py` — new `reattach()` method + helper
Add a method that, given an `instance_id` + `pid`, checks whether that OS process is alive (via `os.kill(pid, 0)`) and, if so, wraps it back into a `TrackedProcess` exactly as `spawn()` does:
- Build a `TrackedProcess` around an **unowned** `asyncio`-friendly process handle. Since we can't re-open the original pipes, use a lightweight wrapper: create a tiny shim object with `.pid`, `.returncode` (None while alive), and an async `.wait()` that polls `os.kill(pid,0)` / `waitpid` (ECHILD => already reaped by init) on a short interval until the process dies. Avoids needing `/proc` or extra deps.
- Restart the **waiter** task (so we still update DB → `exited`/`crashed` when the binary finally dies).
- Restart the **tailer** task (so a late `join_link:` is still captured if not already present). Resume from current EOF so we only scan new log lines.
- Re-arm the **timeout** using the stored `timeout_at`: compute `delay = (parse(timeout_at) - now)`. If already past → kill now (`_kill(timeout_status=True)`). If positive → `schedule_timeout(id, delay)`.

Add a `_pid_alive(pid)` helper using `os.kill(pid, 0)` (returns False on `ProcessLookupError`; True on `PermissionError` since the process exists but is owned by another uid — shouldn't happen under the same service user, but handle defensively).

Process-group note: `start_new_session=True` means the binary is its own session/group leader with `pgid == pid`. The waiter polling `os.kill(pid, 0)` tracks the leader, which is sufficient — when the leader dies the call typically ends too.

### 2. `main.py` — replace `_reconcile_stale_instances()` with a re-adopt flow
Instead of marking all live rows `crashed`:
- `SELECT id, pid, timeout_at, output_link FROM instances WHERE status IN ('pending','running','stopping')`.
- For each row:
  - `pid` is NULL or `_pid_alive(pid)` is False → mark `crashed` (genuinely gone). Keep current error message.
  - `pid` alive → call `process_manager.reattach(id, pid, timeout_at, has_output_link=bool(output_link))`. Leave DB status as-is (`running`).
- Log a summary: `Re-adopted N live instance(s), marked M crashed`.

Note: `process_manager.start()` must run (so the reaper loop exists) but `reattach` is a standalone async call — order: `await process_manager.start()` first, then re-adopt, so reattached waiters/tailers can rely on the reaper running.

### 3. No schema/migration changes
All needed columns (`pid`, `timeout_at`, `output_link`) already exist in the `instances` table. No DB migration required.

## Edge cases handled
- **PID reuse by an unrelated process:** accepted risk (same as any pid-based reattach). Mitigated because this only runs against rows the DB says are live, and only at the narrow restart window. The polling waiter will still correctly detect final exit.
- **Binary already exited during downtime:** `_pid_alive` returns False → marked `crashed` honestly.
- **`timeout_at` in the past at startup:** reattach still wraps it, then immediately schedules the timeout killer which fires and runs `_kill(timeout_status=True)` → status `timeout`. Honest + correctly enforced.
- **`timeout_at` NULL (very old rows):** reattach without rescheduling a timeout (no auto-kill); the instance is supervised but never times out, matching pre-existing behavior for rows lacking a deadline.
- **Server hard crash / power loss (not a clean restart):** identical flow — orphaned binaries that are still alive get re-adopted; dead ones get marked crashed.
- **systemd `KillMode=mixed` + SIGINT:** uvicorn gets SIGINT, children in their own session are NOT signaled → they survive → reattach succeeds. This is the exact scenario being fixed. (No change to the unit file required.)

## Files touched
- `process_manager.py` — add `_pid_alive()`, `_UnownedProc` shim, `reattach()` method.
- `main.py` — rewrite `_reconcile_stale_instances()` to re-adopt live PIDs instead of blanket-crashing.
